# 检索增强生成（RAG）原理

## 1. 什么是 RAG

RAG（Retrieval-Augmented Generation，检索增强生成）是把**检索（Retrieval）**和**生成（Generation）**结合起来的架构：模型在回答前，先从外部知识库中检索出与问题相关的证据片段，再把片段拼进提示词，让大模型"基于证据"生成答案。

它解决的核心问题是**幻觉（Hallucination）**：大模型靠参数化记忆生成内容，遇到训练数据里没有或更新较晚的信息时会一本正经地编造。RAG 通过检索真实证据片段来"约束"生成，让回答有据可依，从而显著降低幻觉、提升可信度与时效性。

## 2. RAG 的标准流程

RAG 分三个阶段：

1. **检索（Retrieval）**：把用户问题转为向量，用向量相似度在知识库中召回最相关的 top-k 个片段。
2. **增强（Augmentation）**：将检索到的片段与用户问题一起组装成提示词，告诉模型"只依据这些片段回答"。
3. **生成（Generation）**：大模型基于增强后的提示词生成最终答案，并在回答中标注引用的来源。

可以用一个"离线的知识库构建 + 在线的问答检索"两个阶段来理解：离线阶段把文档切块、向量化、建索引；在线阶段对问题向量化、检索、拼装、生成。

## 3. RAG 与微调的区别

- **微调（Fine-tuning）**：修改模型本身的参数，把新知识"写进"权重里。成本高、需要高质量标注数据、训练时间长，且更新知识要重新训练。
- **RAG**：不改模型参数，知识放在外部向量库中。更新知识只需重建索引，成本低、速度快，还能明确给出出处。

实践中的搭配是：**复杂推理能力靠模型本身（预训练+少量微调），事实性知识靠 RAG 检索补充**。两者不是互斥的，很多产品是"RAG + 轻量微调"组合使用。

## 4. RAG 的局限与改进

- **检索质量决定上限**：召回片段不相关，答案就会错。所以召回率、向量库质量很关键。
- **多跳问题**：一个问题需要跨多篇文档推理时，单次检索不够，衍生出 Agentic RAG（用 Agent 规划多次检索）。
- **重排序（Rerank）**：先粗召回再精排，可以进一步提升片段与问题的匹配度。
- **上下文污染**：片段太多太长反而干扰生成，需要控制 top_k 与片段长度。

## 5. 小结

- RAG = 检索 + 增强 + 生成，核心价值是降低幻觉、提供出处、知识实时可更新。
- 与微调相比，RAG 不改模型参数、更新快、成本低、可溯源。
- 常见误区：RAG 不只是"把检索结果拼进 prompt"，其关键在于用检索证据"约束"生成，并保证片段与问题相关、答案可追溯。
