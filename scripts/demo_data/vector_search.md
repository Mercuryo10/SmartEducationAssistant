# 向量检索与语义嵌入

## 1. 什么是 Embedding

Embedding（嵌入）是把文本、图片等非结构化数据映射成**稠密向量**（一串浮点数，如 1024 维）的技术。语义相近的内容，它们的向量在空间中距离也近。例如"Attention 机制"与"自注意力"语义接近，向量相似度就高；与"吃饭"则相距很远。

Embedding 由专门的模型（如 text-embedding-v4、bge-m3）生成，其输入是文本，输出是固定维度的向量。这是"语义检索"的基础：把比较文字变成了比较向量。

## 2. 相似度计算

比较两个向量"像不像"，常用两种度量：

- **余弦相似度（Cosine Similarity）**：计算两个向量夹角的余弦值，取值 [-1, 1]，越接近 1 越相似。对文本长度不敏感，是语义检索最常用的度量。
- **内积（Dot Product）**：两个向量逐维相乘再求和。若先对向量做 L2 归一化，则内积等价于余弦相似度。

这也是很多向量库（FAISS）的默认做法：`IndexFlatIP`（内积）+ 向量归一化 ≈ 余弦相似度。

## 3. 向量库：FAISS 与 Milvus

检索成千上万个向量时不能暴力全算，需要**向量数据库 / 向量索引**：

- **FAISS**：Meta 开源的相似性搜索库，适合单机、内存级数据量，开发与原型常用。它提供 `IndexFlatIP`（精确）、`IndexIVF`（倒排，近似但更快）等索引。
- **Milvus**：开源分布式向量数据库，支持海量数据、持久化、云原生部署，适合生产环境。

两者对上层提供相似的能力：添加向量、按相似度检索 top-k、按文档删除。本项目把这一层抽象成 `VectorStore` 接口，开发用 FAISS、生产切 Milvus，业务代码不变。

## 4. RAG 里的检索链路

向量检索在 RAG 中的典型链路：

1. 离线：把文档切块 → 每块用 Embedding 模型转成向量 → 写入向量库。
2. 在线：把用户问题转成向量 → 在向量库中检索 top-k 最相似片段 → 拼进提示词让大模型生成回答。

衡量检索质量的核心指标是**召回率（Recall@K）**：真实相关片段有多大比例被检索到。召回率不高，后面的生成就"无米下锅"。

## 5. 小结

- Embedding 把文本变成语义向量，语义相近则向量相近。
- 余弦相似度（或归一化后的内积）是常用的向量相似度度量。
- FAISS（单机精确/近似检索）与 Milvus（分布式向量库）是常见的两个后端，均可抽象成统一接口。
- 检索是 RAG 的地基：召回质量决定回答质量，常用 Recall@K 衡量。
