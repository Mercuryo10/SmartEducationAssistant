# 02 · 环境搭建与运行验证：让项目跑起来

> 目标：亲手把项目跑起来，并理解「一次请求从发出到返回」的完整链路。**先会跑，再会读。**

---

## 1. conda 是什么？为什么用虚拟环境？

- conda 能创建互相隔离的 Python 环境（不同项目要不同版本/包，互不干扰）。
- 本项目环境叫 `edumentor`（Python 3.11），之前已创建好：
  ```bash
  conda activate edumentor        # 进入环境
  python --version                # 应显示 3.11.x
  ```
- 不激活环境时，你用的是系统 Python（3.10），装错环境会各种报错——**时刻确认自己激活了 edumentor**。

## 2. requirements.txt：项目的"购物清单"

- 里面是项目需要装的全部依赖（fastapi、sqlalchemy、faiss……）。
- 作用：`pip install -r requirements.txt` 一键装齐；换电脑/换服务器也能装出一模一样的环境。
- 阶段一实际只需其中一部分（重依赖 paddleocr/faster-whisper 在后续阶段才用，已装 core 部分）。

## 3. .env 与 .env.example：密钥管理

- `.env.example` 是**模板**（占位符），`.env` 是**真实配置**（含你的 API Key）。
- 工作流：`cp .env.example .env` → 在 `.env` 里填真实值。
- **为什么 `.env` 不能提交 git？** 因为里面有密钥。`API Key 泄露 = 别人拿你的钱调用大模型**。`.gitignore` 里已写了 `.env`，git 会自动忽略它。
- 看一眼 `app/core/config.py` 底部：`settings = Settings()` 启动时就会读 `.env`。

## 4. 让项目跑起来（三步）

```bash
conda activate edumentor

# ① 建库（已经跑过一次，可重复跑，幂等=不会重复创建）
python scripts/init_db.py

# ② 启动服务
uvicorn app.main:app --reload --port 8000
```

- `uvicorn` 是 Python 的 Web 服务器；`app.main:app` = 「模块 `app.main` 里的对象 `app`」。
- `--reload`：改代码自动重启（开发方便）。`--port 8000` 指定端口。

启动后浏览器打开：
- http://localhost:8000 → 前端页面
- http://localhost:8000/docs → Swagger 接口文档（自动生成）
- http://localhost:8000/api/v1/health → 健康检查

## 5. 一次请求的生命周期（以 health 为例）

你在浏览器输入 `http://localhost:8000/api/v1/health`：

```
浏览器
  │  ① HTTP GET /api/v1/health
  ▼
uvicorn（监听 8000 端口）
  │  ② 把请求交给 FastAPI 应用（app.main 里的 app）
  ▼
FastAPI 路由匹配
  │  ③ 匹配到 app/api/health.py 里 @router.get("/health") 的函数
  ▼
health_check() 执行
  │  ④ 调用 services/health_service.py 的 check_database() / check_llm_config()
  ▼
check_database() 用 engine 连 MySQL，执行 SELECT 1
  │  ⑤ 得到结果 dict
  ▼
FastAPI 把 dict 序列化成 JSON 返回给浏览器
```

> 记住这条链路：**URL → 路由函数 → 业务服务 → 数据层 → 返回 JSON**。整个项目所有接口都长这样。

## 6. 动手验证（每个都亲自跑一遍）

```bash
# ① 健康检查（对比 docs/04 §9 的预期响应）
curl http://localhost:8000/api/v1/health
#   期望：{"status":"ok","app":"EduMentor","version":"0.1.0","db":"ok","llm":"ok"}

# ② Swagger 是否打开（200 就是 OK）
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8000/docs

# ③ 前端页面
curl -s http://localhost:8000/ | head -20

# ④ 看数据库里被 init_db 建出来的表和数据
mysql -uedumentor -pedumentor123 -D edumentor -e "SHOW TABLES; SELECT id,username,role FROM users;"
```

## 7. 常见错误排查

| 现象 | 原因/解决 |
|------|-----------|
| `ModuleNotFoundError` | 没激活环境，或 `uvicorn` 不在 `edumentor` 里；确认 `conda activate edumentor` |
| 端口被占用 | 换端口：`uvicorn app.main:app --port 8001` |
| 连接 MySQL 报 Access denied | 检查 `.env` 的 `DATABASE_URL` 账号密码；确认已 `python scripts/init_db.py` |
| `pymysql` 报 cryptography 缺失 | 装 `pip install cryptography` |
| 改了代码不生效 | `--reload` 没生效时手动重启 uvicorn |
