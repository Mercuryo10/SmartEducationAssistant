# 评测方案（AI 数据生成 + Agent 量化评测）

> 配套文档：`00-项目总览.md`（技术基线）· `09-开发计划与验收.md`（阶段九）。
> 目的：解决两个问题——**① 自己没有真实数据，需要用 AI 生成评测数据；② 需要每个 Agent 的量化指标**，用于面试展示（"RAG 回答准确率 87%、客观题判分 100%、练习题可解率 95%"这类可量化的结论）。
> 评测领域：**大模型 / Agent 学习**（面向想学大模型的大学生）。
> 代码位置：`scripts/eval/`；数据位置：`data/eval/`；报告位置：`reports/`。

## 1. 设计原则

1. **数据由 AI 生成 + 人工抽检**：LLM 批量生成样本，抽样 20% 人工修正作为 **golden set**（评测以 golden 为准）。
2. **评测可复现**：固定 `seed`，同一份 golden set 每次跑结果一致。
3. **数据量不求大**：每类数据集 30~100 条即可支撑校招结论；生成成本低（千问/DeepSeek API）。
4. **指标真实**：统计必须来自真实运行结果，禁止虚构数字（答辩可能被追问）。
5. **领域统一**：所有样本基于「大模型/Agent 学习」知识点与 `demo_data/` 知识库。

## 2. AI 数据生成管线

### 2.1 生成脚本结构

```
scripts/eval/
├── generate_datasets.py      # 用当前 LLM_PROVIDER 生成全部数据集
├── datasets.py               # 数据集 schema 定义与读写（JSONL）
└── ...
data/eval/
├── raw/                      # LLM 原始生成（未审核）
└── golden/                   # 人工抽检后的最终评测集
```

运行：`python scripts/eval/generate_datasets.py --seed 42`（输出 golden 前先人工审核一轮，见 §2.3）。

### 2.2 数据集定义（JSONL schema）

#### ① 问答评测集 `qa_pairs.jsonl`（测智能答疑 + RAG 检索）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | int | 样本号 |
| `question` | str | 问题（如「RAG 为什么能缓解幻觉？」） |
| `reference_answer` | str | 参考答案（从知识库片段提炼） |
| `source_doc_id` | int | 答案应引用的知识库文档（用于溯源正确性） |
| `difficulty` | str | easy / medium / hard |

生成方式：从 `knowledge_docs` 抽取片段 → LLM 生成「问题 + 参考答案 + 对应 doc_id」。

#### ② 作业批改样本集 `grading_samples.jsonl`（测批改 + OCR）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | int | 样本号 |
| `question_type` | str | choice / fill / short_answer |
| `question` | str | 题干（大模型领域概念题） |
| `reference_answer` | str | 参考答案 |
| `student_answer` | str | 学生作答（**含故意写错的**） |
| `expected_correct` | bool | 客观题：期望对错（程序可判定） |
| `expected_score` | int | 主观题：期望分数（LLM 初版 + 人工复核） |

> OCR 评测：额外准备 `data/eval/ocr_imgs/` 几张"含已知文字的题目截图/试卷图"，用 `ocr_extract` 输出与 ground truth 比对算字准率。

#### ③ 错题样本集 `mistake_samples.jsonl`（测知识点分类）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | int | 样本号 |
| `question` | str | 题目 |
| `wrong_answer` | str | 错误作答（如"RAG 只是把检索结果拼进 prompt"） |
| `correct_answer` | str | 正确作答 |
| `knowledge_point` | str | 期望关联的知识点（如「检索增强生成 RAG」） |

#### ④ 练习题统计集（测练习生成）

- 不设 golden：由 `exercise_agent` 按参数批量生成 50~100 题，仅统计**可解率 / 难度分布 / 去重率**。

### 2.3 生成与审核流程

1. 运行 `generate_datasets.py` 产出 `data/eval/raw/*.jsonl`。
2. 人工抽检：随机 20% 样本修正错误 → 标记为 golden（写入 `data/eval/golden/`）。
3. 评测一律用 **golden**；raw 仅作生成回放。

> 人工审核工作量约 1~2 小时（每类 20 条左右），校招可接受。

## 3. Agent 量化评测指标

### 3.1 智能答疑 Agent

| 指标 | 定义 | 计算 |
|------|------|------|
| 检索命中率（Recall@5） | 参考答案 `source_doc_id` 是否出现在检索 top-5 结果中 | 命中样本数 / 总样本 |
| 回答准确率 | 生成回答与 `reference_answer` 的语义一致程度 | **LLM-as-judge** 打分（0-100）取平均；或关键词/相似度匹配阈值 |
| 忠实度（Faithfulness） | 回答是否全部源于检索片段（不编造） | LLM-judge 判定「回答中是否有片段外事实」的比例 |
| 溯源正确率 | `source_refs` 中是否包含 `source_doc_id` | 命中 / 总样本 |

### 3.2 作业批改 Agent

| 指标 | 定义 | 计算 |
|------|------|------|
| 客观题判分准确率 | 判分结果与 `expected_correct` 一致 | 一致样本 / 客观题样本 |
| 主观题评分误差（MAE） | AI 评分与 `expected_score` 的平均绝对误差 | mean(\|ai - expected\|) |
| OCR 字准率（CER） | OCR 文本与 ground truth 的编辑距离 | 1 - 编辑距离/总字符数（对 `ocr_imgs/`） |

### 3.3 错题分析 Agent

| 指标 | 定义 | 计算 |
|------|------|------|
| 知识点分类 Top-1 准确率 | 自动关联的知识点与 `knowledge_point` 一致 | 一致 / 总样本 |

### 3.4 练习生成 Agent

| 指标 | 定义 | 计算 |
|------|------|------|
| 可解率 | 生成题目答案代入验算通过的比例 | 通过 / 生成总数 |
| 难度符合率 | 抽样人工判定难度与请求一致 | 一致 / 抽样数 |
| 去重率 | 同参数两次生成内容不重复的比例 | 不重复 / 对比对数 |

### 3.5 学习推送 Agent

| 指标 | 定义 | 计算 |
|------|------|------|
| 按时触发率 | 到期任务在容忍窗口内触发的比例 | 按时 / 到期总数 |
| 推送成功率 | `push_logs` 中 success 的比例 | success / 总任务 |

### 3.6 全局指标

| 指标 | 说明 |
|------|------|
| 端到端时延 | 首 token 时间、完整回答时间（P50 / P95），按 Agent 记录 |
| 常驻内存 RSS | 进程内存（仅加载所需模型时） |
| 接口正确率 | `GET /api/v1/health` 与核心接口无 5xx 的比例 |

## 4. 评测脚本与报告

```
scripts/eval/
├── generate_datasets.py     # §2 数据生成
├── eval_qa.py               # 检索命中率 / 回答准确率 / 忠实度 / 溯源
├── eval_grading.py          # 判分准确率 / MAE / OCR CER
├── eval_mistake.py          # 知识点 Top-1 准确率
├── eval_exercise.py         # 可解率 / 难度符合率 / 去重率
├── eval_push.py             # 按时触发率 / 推送成功率
├── eval_latency.py          # 端到端时延 / 内存
└── run_all.py               # 汇总 → reports/eval_report.md + eval_report.json
```

- 统一入口：`python scripts/eval/run_all.py`（顺序执行各模块，`seed` 固定）。
- 输出 `reports/eval_report.md`：指标表 + 本次运行环境（LLM 提供商 / 向量后端 / 样本数）+ 结论。
- 单模块可单独跑：`python scripts/eval/eval_qa.py`。

### 报告示例（目标值，仅供格式参考）

```markdown

| 指标 | 结果 |
|------|------|
| 检索命中率 Recall@5 | 93.3% |
| 回答准确率（LLM-judge） | 87.5 |

| 主观题评分 MAE | 4.2 分 |
| OCR 字准率 CER | 96.1% |
...
```

## 5. 成本与规模说明

- 数据生成成本：60 条问答 + 60 条批改 + 60 条错题 ≈ 数百次 LLM 调用，费用可忽略（演示级）。
- 评测运行成本：评测跑一遍也是数百次调用，可控。
- 数据量建议起步：每类 **40 条 golden**，答辩结论已足够；时间允许再扩到 100。

## 6. 与开发计划衔接（阶段九）

见 `09-开发计划与验收.md` 阶段九。关键里程碑：

- [ ] `scripts/eval/datasets.py` + `generate_datasets.py`（数据 schema 与生成）
- [ ] 4 类数据集各 ≥40 条 golden（含人工抽检）
- [ ] 各 Agent 评测脚本（§4）跑通，产出 `reports/eval_report.md`
- [ ] 关键指标达成建议阈值：检索命中 ≥85%、客观题判分 ≥95%、练习题可解率 ≥90%、知识点分类 ≥80%
- [ ] 截图/导出报告作为答辩材料

> 说明：LLM-as-judge 打分需复用 `services/llm.py` 的 `get_chat_llm()`（同一提供商），并在报告中注明"judge 模型 = 当前 LLM"。
