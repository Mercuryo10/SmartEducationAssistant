# EduMentor —— 基于多 Agent 协作架构的智能教育助手（项目总览）

> 本文档是全项目的「总索引」与「技术规格基线」。后续所有文档中的端口、接口路径、表名、工具名、依赖版本均以本文档为准。若其他文档与本文档冲突，以本文档为准。

## 1. 项目一句话介绍

EduMentor 是一个面向**想学习大模型/Agent 的大学生**的智能教育助手：通过 **大模型（DeepSeek/本地 Qwen）+ 多 Agent 协作编排（LangGraph）+ 教育专用工具服务层**，实现智能答疑、作业批改、错题分析、练习生成、学习推送五大闭环能力，支持文本 / 图片 / 语音多模态输入，解决「一对多」教学模式下个性化辅导不足的问题。

> 本项目定位为**校招项目**：双模式部署 —— 开发期在**笔记本（Windows）**轻量运行；生产期移植到**实验室 Ubuntu（RTX 4090）**使用企业级中间件（MySQL + Redis + Milvus + 本地模型）。亮点突出（RAG 问答、多模态识别、多 Agent 协作、流式交互、**存储/缓存/LLM 后端可切换**），适合面试演示与答辩。

## 2. 五大功能模块

| # | Agent | 能力 | 技术亮点 |
|---|-------|------|----------|
| 1 | 智能答疑 Agent | 多模态问题解答（文本/图片/语音），知识库 RAG 检索，回答带溯源 | RAG + 向量检索 + 多模态输入 |
| 2 | 作业批改 Agent | 拍照识别作业 → 客观题自动判分 + 主观题 AI 评分反馈 | PaddleOCR + LLM 评分 |
| 3 | 错题分析 Agent | 错题关联知识点 → 薄弱点归纳 → 个性化讲解 | 知识点标签 + 聚类归纳 |
| 4 | 练习生成 Agent | 按知识点/难度/题型参数化出题 | 模板引擎 + 难度控制 |
| 5 | 学习推送 Agent | 基于遗忘曲线的定时复习提醒 | 定时任务 + 多渠道触达(可扩展) |

## 3. 技术栈清单

| 类别 | 开发期（笔记本 Windows） | 生产期（实验室 Ubuntu + RTX 4090） | 说明 |
|------|--------------------------|-----------------------------------|------|
| 运行时 | Python 3.11 | Python 3.11 | 一致 |
| Web 框架 | FastAPI + Uvicorn | 同左 | 端口 **8000**，前缀 `/api/v1` |
| **LLM** | **DeepSeek 云 API**（`deepseek-v4-flash`，OpenAI 兼容） | **本地 Qwen**（Ollama，如 `qwen2.5:14b`，OpenAI 兼容） | `LLM_PROVIDER` 切换 |
| **Embedding** | **千问云 API**（`text-embedding-v4`，1024 维） | **本地 `bge-m3`**（Ollama，1024 维） | `EMBEDDING_PROVIDER` 切换 |
| Agent 框架 | LangChain / LangGraph（最新稳定版） | 同左 | Supervisor 模式 |
| OCR | PaddleOCR（CPU，PP-OCRv4） | 同左（4090 可启用 GPU 加速） | 本地推理 |
| 语音 | faster-whisper `small`（int8，CPU） | faster-whisper `small` 或 `medium`（GPU） | 本地推理 |
| **业务库** | **MySQL 8.0**（本机已装） | **MySQL 8.0**（已部署实例，直接连接） | SQLAlchemy + PyMySQL |
| **向量库** | **FAISS**（`faiss-cpu`） | **Milvus 2.x**（已部署实例，直接连接） | `VECTOR_BACKEND` 切换 |
| **缓存** | **内存 TTL**（cachetools） | **Redis 7.x**（已部署实例，直接连接） | `CACHE_BACKEND` 切换 |
| 定时任务 | APScheduler | 同左 | 学习推送触发 |
| 前端 | 静态单页 HTML/JS（内置于 FastAPI） | 同左 | SSE 流式对话 |
| 部署 | 本机直跑 | **直接连接已部署的 MySQL/Redis/Milvus** + 本地模型；compose 仅备用 | 迁移见 `07` |

> **设计亮点**：存储、缓存、LLM/Embedding 全部通过**接口抽象 + 配置切换**，开发与生产使用同一套代码，仅 `.env` 不同。这是简历上值得强调的「可移植性」设计。

> **与 `项目介绍.md` 原始方案的差异**：原始方案指定 LangChain 0.1.17 / LangGraph 0.0.45 / FastAPI 0.103.2、Qwen-plus、4×A10 GPU 集群。本项目按校招场景做了适配（详见 `02-系统架构设计.md` 的「术语对照表」与 `05-Agent编排设计.md` 的「版本差异」章节）。编码时以**本文档与最新稳定版官方文档为准**。

## 6. 快速开始（摘要，详见 `07-部署与运行指南.md`）

```bash
# 1. 准备环境
conda create -n edumentor python=3.11 -y && conda activate edumentor
pip install -r requirements.txt

# 2. 准备 MySQL：创建数据库与用户（详见 07 §3）
mysql -uroot -p -e "CREATE DATABASE IF NOT EXISTS edumentor CHARACTER SET utf8mb4;"

# 3. 配置 .env（填入 DeepSeek / 千问 API Key；开发默认 FAISS + 内存缓存）
cp .env.example .env

# 4. 初始化数据库 + 构建样例知识库
python scripts/init_db.py
python scripts/build_kb.py

# 5. 启动
uvicorn app.main:app --reload --port 8000
# 打开 http://localhost:8000 即可体验 Web 页面
```

## 9. 本项目的「面试讲解主线」（给用户）

1. **为什么多 Agent**：单一 prompt 无法同时做好「答疑、批改、错题、出题、推送」五类专业任务；拆分为专业 Agent + 统一编排，职责单一、可独立迭代。
2. **决策层如何路由**：Supervisor 用 LLM 函数调用做意图分类，把请求分派到对应子 Agent 子图（对应原始方案中的 Function Call 决策层）。
3. **工具层如何复用**：OCR / 语音 / 检索等被多个 Agent 复用的能力抽成独立工具（对应 MCP 工具服务层），且支持扩展成标准 MCP Server。
4. **后端可切换设计（加分项）**：向量库（FAISS↔Milvus）、缓存（内存↔Redis）、LLM（DeepSeek↔本地 Qwen）全部接口化 + 配置切换，同一套代码从笔记本平滑迁移到实验室 Ubuntu 生产环境 —— 体现真实工程的可移植性。
