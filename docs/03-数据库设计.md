# 数据库设计

> 配套文档：`00-项目总览.md`（技术基线/环境变量）· `02-系统架构设计.md`（数据访问层）· `08-开发规范与编码约定.md`（ORM 约定）· `07-部署与运行指南.md`（MySQL 建库/中间件）。
> 存储后端：**MySQL 8.0**（业务数据，全期一致）+ **向量库后端**（开发 FAISS / 生产 Milvus）+ **缓存后端**（开发内存 TTL / 生产 Redis）。三者均接口抽象、配置切换。

## 1. 设计原则

1. **MySQL 为主库**：业务数据全部落 MySQL（InnoDB / utf8mb4），驱动 `pymysql`，连接串见 §2。
2. **后端接口化**：向量库 `VectorStore`、缓存 `Cache` 均为接口 + 工厂，开发/生产通过 `VECTOR_BACKEND` / `CACHE_BACKEND` 切换（见 §5、§6）。
3. **仓储化**：所有数据库访问走 `app/storage/repositories/`；未来扩表/换库只改实现不动业务。
4. **时间字段**：统一 `created_at`（创建时间，UTC 存储，展示转本地）。
5. **软删除不做**（校招范围精简），删除即物理删除。
6. **外键**：InnoDB 原生支持外键约束；ORM 用关系字段表达关联。

```python
from sqlalchemy import create_engine

from app.core.config import settings

engine = create_engine(
    settings.DATABASE_URL,
    pool_pre_ping=True,

    echo=(settings.APP_ENV == "dev"),

def get_session():
    with SessionLocal() as s:
        yield s
```

## 4. 表结构定义（MySQL DDL）

> 所有表 `ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci`；JSON 字段用 `JSON` 类型。以下 DDL 为 MySQL 方言，ORM 模型（SQLAlchemy）与之对应。

### 4.1 `users` 用户表

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | BIGINT UNSIGNED | PK, AUTO_INCREMENT | 主键 |
| `username` | VARCHAR(64) | UNIQUE, NOT NULL | 用户名 |
| `password_hash` | VARCHAR(128) | NOT NULL | 密码哈希 |
| `nickname` | VARCHAR(64) | NULL | 昵称 |
| `role` | VARCHAR(16) | DEFAULT 'student' | student / teacher |
| `created_at` | DATETIME | NOT NULL | 创建时间 |

```sql
CREATE TABLE IF NOT EXISTS users (
    id            BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    username      VARCHAR(64)  NOT NULL UNIQUE,
    password_hash VARCHAR(128) NOT NULL,
    nickname      VARCHAR(64),
    role          VARCHAR(16)  NOT NULL DEFAULT 'student',
    created_at    DATETIME     NOT NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

### 4.2 `conversations` 会话表 / `messages` 消息表

```sql
CREATE TABLE IF NOT EXISTS conversations (
    id         BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    user_id    BIGINT UNSIGNED NOT NULL,
    title      VARCHAR(128) NOT NULL DEFAULT '新对话',
    created_at DATETIME     NOT NULL,
    CONSTRAINT fk_conv_user FOREIGN KEY (user_id) REFERENCES users(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

CREATE TABLE IF NOT EXISTS messages (
    id              BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    conversation_id BIGINT UNSIGNED NOT NULL,
    role            VARCHAR(16) NOT NULL,          -- user / assistant / tool
    content         TEXT        NOT NULL,
    source_refs     JSON,                          -- 溯源引用 [{doc_id, source, snippet}]
    created_at      DATETIME    NOT NULL,
    CONSTRAINT fk_msg_conv FOREIGN KEY (conversation_id) REFERENCES conversations(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
CREATE INDEX idx_messages_conv ON messages(conversation_id);
```

### 4.3 `knowledge_docs` 知识库文档表

```sql
CREATE TABLE IF NOT EXISTS knowledge_docs (
    id          BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    title       VARCHAR(255) NOT NULL,
    source      VARCHAR(512) NOT NULL,
    content     TEXT         NOT NULL,
    chunk_count INT          NOT NULL DEFAULT 0,
    created_at  DATETIME     NOT NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

> 分块文本本身存于**向量库索引的元数据**（FAISS 元数据 / Milvus 字段），无需单独 chunk 表；如需更完善溯源可扩展 `knowledge_chunks` 表。

## 5. 向量库后端设计（`app/storage/vector_store.py`）

### 5.1 统一接口

```python
from typing import Protocol

class VectorStore(Protocol):
    """向量库抽象：业务层只依赖本接口。"""
    def add(self, chunks: list[dict]) -> None: ...
        # chunk: {doc_id, title, source, chunk_index, text, vector(list[float])}
    def search(self, vector: list[float], top_k: int = 5) -> list[dict]: ...
        # 返回 [{text, source, doc_id, title, chunk_index, score}]
    def delete_by_doc(self, doc_id: int) -> None: ...
    def rebuild(self) -> None: ...          # 全量重建（从 knowledge_docs 重新切分嵌入）
    def count(self) -> int: ...
```

工厂（读取 `VECTOR_BACKEND`）：

```python
def get_vector_store() -> VectorStore:
    if settings.VECTOR_BACKEND == "milvus":
        return MilvusVectorStore()
    return FaissVectorStore()   # 默认 faiss
```

### 5.2 FAISS 实现（开发期，`VECTOR_BACKEND=faiss`）

| 项 | 取值 | 说明 |
|----|------|------|
| 存储路径 | `VECTOR_INDEX_DIR`（默认 `data/vector_index/`） | `index.faiss` + `index.pkl`（docstore） |
| 索引类型 | `IndexFlatIP`（内积） | 向量 **L2 归一化**后等价余弦相似度 |
| 向量维度 | **1024** | 与 `text-embedding-v4` / `bge-m3` 一致 |
| 分块 | `chunk_size=500, chunk_overlap=50` | `RecursiveCharacterTextSplitter` |
| top_k | **5** | 常量 `RETRIEVE_TOP_K` |

### 5.3 Milvus 实现（生产期，`VECTOR_BACKEND=milvus`）

| 项 | 取值 | 说明 |
|----|------|------|
| 连接 | `MILVUS_HOST`（默认 `127.0.0.1`）/ `MILVUS_PORT`（默认 `19530`） | `pymilvus` 客户端 |
| 集合 | `knowledge_chunks` | 不存在时自动创建 |
| 字段 | `id`(INT64 PK auto)、`doc_id`(INT64)、`chunk_index`(INT64)、`title`(VARCHAR)、`source`(VARCHAR)、`text`(VARCHAR 65535)、`vector`(FLOAT_VECTOR 1024) | — |
| 索引 | `IVF_FLAT`（nlist=1024），metric `COSINE` | 与 FAISS 余弦语义一致 |
| 一致性 | `ConsistencyLevel.SESSION`（会话级） | 演示场景足够 |

**collection 创建（要点）**：

```python
from pymilvus import MilvusClient, DataType
client = MilvusClient(uri=f"http://{host}:{port}")
client.create_collection(
    collection_name="knowledge_chunks",
    dimension=1024,
    metric_type="COSINE",
    primary_field_name="id",
    vector_field_name="vector",
    max_length=65535,
    enable_dynamic_field=False,
)
```

> 生产环境中间件（MySQL/Redis/Milvus）通常**已部署**，`pymilvus` 只需按 `MILVUS_HOST`/`MILVUS_PORT` 连接；MinIO 是 Milvus 内部对象存储，应用不直接连。若目标机未预装，可用根目录 `docker-compose.prod.yml`（**可选/备用**）一键启动（`07` §8）。

## 6. 缓存后端设计（`app/storage/cache.py`）

### 6.1 统一接口

```python
class Cache(Protocol):
    def get(self, key: str) -> str | None: ...
    def set(self, key: str, value: str, ttl_seconds: int = 300) -> None: ...
    def delete(self, key: str) -> None: ...
    def clear(self) -> None: ...

def get_cache() -> Cache:
    if settings.CACHE_BACKEND == "redis":
        return RedisCache()
    return MemoryCache()   # 默认 memory
```

### 6.2 用途与 Key 约定

| 用途 | Key 格式 | TTL |
|------|----------|-----|
| 对话上下文 | `ctx:{conversation_id}` → 最近 N 条消息 JSON | 600s |
| 热点 RAG 答案 | `rag:{hash(query)}` → 答案 JSON | 300s |
| OCR/ASR 结果去重 | `media:{file_sha256}` → 文本 | 3600s |

### 6.3 MemoryCache（开发期，`CACHE_BACKEND=memory`）

- 基于 `cachetools.TTLCache(maxsize=1024)`，进程内存。
- 注意：重启即失效；仅单进程有效。

### 6.4 RedisCache（生产期，`CACHE_BACKEND=redis`）

- 基于 `redis` 包：`Redis.from_url(settings.CACHE_URL)`（默认 `redis://127.0.0.1:6379/0`）。
- TTL 由 Redis `EXPIRE` 实现；`clear()` 用 `flushdb()`（仅当库专用）。
- 阻塞调用在 FastAPI 中放线程池（`def` 路由）执行。

## 7. 仓储层接口（替换点清单）

`app/storage/repositories/` 目录结构：

```
repositories/
├── __init__.py            # 汇总导出
├── base.py                # 抽象基类：通用 CRUD（get/create/update/delete/list）
├── user_repo.py
├── conversation_repo.py   # 会话 + 消息
├── knowledge_repo.py      # knowledge_docs + knowledge_points
├── homework_repo.py       # submissions + grading_results
├── mistake_repo.py
├── exercise_repo.py       # exercises + generated_exercises
└── push_repo.py           # push_tasks + push_logs
```

**约定**：每个 Repository 只操作自己的表；方法命名 `get_*` / `create_*` / `update_*` / `delete_*` / `list_*`；返回 ORM 对象或字典，不返回 SQL。

> 本项目存储后端已接口化（`VectorStore`/`Cache`），业务层零感知。若未来数据库从 MySQL 换 PG，仅需改 `DATABASE_URL` 与少量方言 SQL。
