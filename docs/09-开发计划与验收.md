# 开发计划与验收

> 配套文档：`00-项目总览.md`（技术基线）· `01-需求规格说明书.md`（需求）· `08-开发规范与编码约定.md`（编码规范）。
> 本文件定义 **AI coding 的分阶段构建顺序**。原则：**每阶段结束必须可独立启动、可验证，再进入下一阶段**，禁止一次性铺开全部代码。

## 0. 总则

- 每个阶段结尾做一次「可运行性验收」（见各阶段清单），通过后才能继续。
- 每完成一个 Agent，跑一遍 `08-开发规范与编码约定.md` §11 自查清单。
- 存储/缓存/LLM **一律走接口与工厂**（`VectorStore` / `Cache` / `llm.py`），开发期默认 `faiss`+`memory`+云端模型，生产期切 `milvus`+`redis`+本地模型。
- 全部完成后执行 §7 端到端验收 + §8 Ubuntu 生产验收。

## 1. 阶段一：项目骨架（Skeleton）

**目标**：可启动的 FastAPI 空壳 + 配置 + MySQL 数据层 + 后端接口抽象。

**交付物**：

- [ ] 目录结构（`00-项目总览.md` §5）、`requirements.txt`、`.env.example`、`.gitignore`、`docker-compose.prod.yml`
- [ ] `app/core/config.py`（含全部双模式配置项）、`logging.py`、`exceptions.py`
- [ ] `app/main.py`：创建 app、挂 `/api/v1/health`、托管 `app/static/index.html`
- [ ] `app/storage/db.py`（MySQL engine/session）、`models.py`（全部表，`03` §4）、`init_db.py`
- [ ] `app/storage/cache.py`：`Cache` 接口 + `MemoryCache` + `get_cache()` 工厂
- [ ] `app/storage/vector_store.py`：`VectorStore` 接口 + `FaissVectorStore` + `get_vector_store()` 工厂
- [ ] `app/storage/repositories/`：base + 各 repo
- [ ] `app/schemas/`：auth/chat/homework/mistake/exercise/push 的 Pydantic 模型
- [ ] `app/services/llm.py`：`get_chat_llm()` / `get_embedding_client()` 工厂（DeepSeek + 千问）

**验收**（需先按 `07` §3 建好 MySQL 库与用户）：

```bash
python scripts/init_db.py                  # 成功；重复运行幂等
uvicorn app.main:app --port 8000
curl http://localhost:8000/api/v1/health   # {"status":"ok",...}
curl http://localhost:8000/docs            # Swagger 可打开
python -c "from app.storage.cache import get_cache; from app.storage.vector_store import get_vector_store; print(get_cache(), get_vector_store())"  # 返回 Memory/Faiss 实例
```

## 2. 阶段二：智能答疑 Agent（P0 核心，先打通 RAG）

**目标**：文字问答 RAG 闭环 + SSE 流式 + 溯源（开发后端：千问 Embedding + FAISS）。

**交付物**：

- [ ] `app/services/rag_service.py`（检索 + 溯源组装，只依赖 `VectorStore` 接口）
- [ ] `app/services/ocr_service.py`、`asr_service.py`（惰性单例占位可调用）
- [ ] `app/tools/ocr_tool.py`、`asr_tool.py`、`retrieval_tool.py`
- [ ] `app/agents/state.py`、`qa_agent.py`（preprocess→retrieve→generate→persist）
- [ ] `scripts/build_kb.py` + `scripts/demo_data/`（≥3 个大模型/Agent 领域知识点文档，如注意力机制 / RAG 原理 / Agent 工作流）
- [ ] `app/api/chat.py`（SSE）、`app/api/auth.py`、conversations/messages 接口
- [ ] `app/static/index.html`：对话面板（文本输入 + 流式渲染 + 溯源展示）

**验收**（对照 `01` US-QA-*）：文字提问流式返回且 `done` 含 `source_refs`；无相关知识明确说明；多轮追问可结合上文；图片/语音提问（US-QA-2/3）。

## 3. 阶段三：作业批改 Agent（P0 核心）

**目标**：图片 → OCR → 客观题自动判分 + 主观题 AI 评分。

**交付物**：`grading_tool.py`（`grade_objective`）、`grading_agent.py`、`app/api/homework.py`、`homework_repo.py`、样例图 `scripts/demo_data/homework_demo.jpg`。

**验收**（对照 US-GR-*）：样例图返回逐题明细；客观题对错正确；主观题 `is_ai_scored=true`；OCR 失败不阻塞；`GET /homework/submissions/{id}` 可复现。

## 4. 阶段四：错题分析 Agent（P0 核心）

**交付物**：`knowledge_tool.py`、`mistake_agent.py`、`app/api/mistakes.py` + knowledge-points 接口、`mistake_repo.py`。

**验收**（对照 US-MS-*）：录入自动关联知识点；列表可按知识点过滤；薄弱点 TopN 真实；`analyze` 返回结构化解讲。

## 5. 阶段五：练习生成 Agent（P1）

**交付物**：`exercise_tool.py`（模板填充 + 可解校验）、`exercise_agent.py`、`app/api/exercises.py`、模板数据（≥3 题型「选择/填空/简答」× ≥3 个大模型/Agent 知识点）。

**验收**（对照 US-EX-*）：参数化出题；两次生成不同；含 answer/explanation；easy/hard 差异明显；答案代入验算通过。

## 6. 阶段六：学习推送 Agent（P1）

**交付物**：`push_tool.py`（渠道分发 mock 默认）、`push_agent.py`、`scheduler.py`（APScheduler 每 30s 扫描）、`app/api/push.py`、`push_repo.py`。

**验收**（对照 US-PU-*）：`/push/plan` 按 1/2/4/7 天生成 4 个复习点；5 分钟后任务触发且 `push_logs` 出现 success；服务重启后任务恢复。

## 7. 阶段七：编排整合 + 双后端实现 + 前端 + 端到端验收

**目标**：LangGraph Supervisor 统一入口；**实现 Milvus / Redis 后端实现**；前端五面板；全链路验收。

**交付物**：

- [ ] `app/agents/supervisor.py`（`05` §4，含 `route_to_agent`）
- [ ] 5 个子 Agent 统一为 `build_subgraph()`，挂入主图
- [ ] `app/storage/vector_store.py` 增加 `MilvusVectorStore`；`app/storage/cache.py` 增加 `RedisCache`（工厂按配置返回）
- [ ] `app/api/chat.py` 走主图（其余接口独立可调）
- [ ] `app/static/index.html`：答疑 / 批改 / 错题 / 出题 / 推送 五个 Tab
- [ ] `app/tests/`：核心单测（`08` §10）

**端到端验收清单**：

```bash
python scripts/init_db.py && python scripts/build_kb.py
uvicorn app.main:app --port 8000
```

- [ ] 浏览器五个 Tab 均可操作；文字提问走 Supervisor → QA 子图 → 流式回答 + 溯源
- [ ] 批改 / 错题 / 出题 / 推送 四面板各自可用
- [ ] `python -m pytest app/tests -v` 通过
- [ ] `curl http://localhost:8000/api/v1/health` 正常
- [ ] `get_vector_store()` / `get_cache()` 在 `VECTOR_BACKEND=faiss` / `CACHE_BACKEND=memory` 下仍返回原实现（后端切换不破坏既有功能）

> 说明：Milvus / Redis 实现写完后，在本机无中间件时**不可被选中运行**（工厂按配置返回）。可在本机用 Docker 临时验证（可选），正式验证在阶段八。

## 8. 阶段八：Ubuntu 生产部署与验收（RTX 4090）

**目标**：把项目按生产模式部署到实验室服务器，验证企业级中间件 + 本地模型全链路。

**操作步骤**（详见 `07` §8~9）：

- [ ] 确认 MySQL/Redis/Milvus 已在服务器运行并可达；`DATABASE_URL` / `CACHE_URL` / `MILVUS_HOST/PORT` 指向正确（未预装中间件时再 `docker compose -f docker-compose.prod.yml up -d`，可选）
- [ ] Ollama 部署 `qwen2.5:14b` + `bge-m3`；`curl http://localhost:11434/v1/models` 可访问
- [ ] `.env` 切生产值：`LLM_PROVIDER=local`、`EMBEDDING_PROVIDER=local`、`VECTOR_BACKEND=milvus`、`CACHE_BACKEND=redis`、`APP_ENV=prod`
- [ ] `pip install -r requirements.txt`；`python scripts/init_db.py`；`python scripts/build_kb.py`（索引写入 Milvus）
- [ ] `uvicorn app.main:app --host 0.0.0.0 --port 8000`

**生产验收清单**：

- [ ] `GET /api/v1/health` 返回 ok
- [ ] curl 一条答疑流式请求 → 本地 Qwen 回答 + Milvus 检索溯源（验证本地 LLM + Milvus 链路）
- [ ] 中间件连通性验证：`redis-cli ping` → `PONG`；MySQL 可连；Milvus 检索命中（compose 部署时 `docker compose ps` 全绿）
- [ ] 批改接口可用（PaddleOCR 在服务器跑通，必要时装 `libgl1`）
- [ ] 推送任务触发后 `push_logs` 有记录（验证 Redis 缓存不影响调度）
- [ ] **代码零改动**完成迁移（只改 `.env`）

## 9. 阶段九：AI 数据生成与 Agent 量化评测

**目标**：补齐「数据」与「量化指标」，产出可用于答辩的评测报告（自己没数据 → 用 AI 生成；需要量化结果 → 逐 Agent 评测）。详见 `10-评测方案.md`。

**交付物**：

- [ ] `scripts/eval/datasets.py`（数据集 schema）+ `generate_datasets.py`（AI 生成）
- [ ] 4 类评测数据集（问答 / 批改 / 错题 / 练习题统计）各 ≥40 条 golden（含人工抽检，见 `10` §2.3）
- [ ] 各 Agent 评测脚本：`eval_qa.py` / `eval_grading.py` / `eval_mistake.py` / `eval_exercise.py` / `eval_push.py` / `eval_latency.py` / `run_all.py`
- [ ] `reports/eval_report.md`（指标表 + 运行环境 + 结论）
- [ ] 答辩材料：指标截图 + 报告导出

**验收（指标阈值）**：

- [ ] 检索命中率 Recall@5 ≥ 85%
- [ ] 客观题判分准确率 ≥ 95%
- [ ] 练习题可解率 ≥ 90%
- [ ] 知识点分类 Top-1 准确率 ≥ 80%
- [ ] `python scripts/eval/run_all.py` 一次跑通，指标真实可复现

> 说明：数据生成与评测在开发期（云端 LLM）完成即可；迁移 Ubuntu 后如条件允许可对本地模型重跑一次，对比两套模型指标（答辩加分点）。

## 11. 风险与预案

| 风险 | 预案 |
|------|------|
| MySQL 8 认证插件与 `pymysql` 兼容 | `pip install cryptography`；或改用 `mysqlclient` 驱动 |
| Milvus / Redis 本机无法起 | 开发期用 FAISS + 内存缓存，不影响进度；生产期连已部署中间件（未预装才用 compose 备用方案） |
| DashScope/DeepSeek 兼容模式与 LangChain 版本偶合 | 用 `langchain-openai` 官方封装；报错按 `pip show` 查官方文档 |
| PaddleOCR / faster-whisper 安装困难 | 工具返回「未就绪」错误信息；或临时换 `easyocr`/云端 ASR |
| 流式 SSE 接入复杂 | 降级为整段返回 JSON（保留 SSE 事件格式，一次 `done`） |
| 本地 Qwen 14B 在 4090 上 OOM | 换 `qwen2.5:7b` 或 `qwen2.5:14b` 的 Q4 量化；或加 `--num-gpu-layers` 调优 |
| 生产与开发行为不一致 | 后端差异已收敛到接口 + `.env`；迁移后务必重跑 `build_kb.py`（向量库换后端） |
