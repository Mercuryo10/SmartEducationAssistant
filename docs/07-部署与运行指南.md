# 部署与运行指南

> 配套文档：`00-项目总览.md`（环境变量基线）· `03-数据库设计.md`（初始化脚本）· `09-开发计划与验收.md`（分阶段验证）。
> 两种运行模式：**开发期**（笔记本 Windows，MySQL 本机 + FAISS + 内存缓存 + 云端 LLM）与**生产期**（实验室 Ubuntu + RTX 4090，MySQL/Redis/Milvus 全中间件 + 本地模型）。**同一套代码，只改 `.env`**。

## 1. 前置准备

| 项 | 开发期（笔记本） | 生产期（Ubuntu + 4090） |
|----|------------------|--------------------------|
| Python | 3.11 | 3.11 |
| MySQL | 本机已装 8.0 | **已部署实例**（直接连接） |
| 中间件 | 无（FAISS + 内存缓存） | **已部署**：Redis + Milvus（含其内部 MinIO） |
| 本地模型 | 无（LLM/Embedding 走云端 API） | Ollama：`qwen2.5:14b` + `bge-m3` |
| API Key | DeepSeek + 千问 | 不需要 |
| 磁盘 | ≥ 5GB | ≥ 20GB（模型 + 中间件镜像） |

## 2. 环境搭建（开发期）

### 2.1 创建虚拟环境

```bash
conda create -n edumentor python=3.11 -y
conda activate edumentor
# 或 venv： python -m venv .venv && .venv\Scripts\activate
```

### 2.2 安装 PaddleOCR（CPU）与项目依赖

```bash
# PaddlePaddle CPU 版 + PaddleOCR（注意：本项目用 2.x API，勿装 3.x）
python -m pip install paddlepaddle==2.6.1 -i https://mirror.baidu.com/pypi/simple
python -m pip install paddleocr>=2.7,<3.0 -i https://mirror.baidu.com/pypi/simple

pip install -r requirements.txt
```

> 首次运行 OCR 会自动下载 PP-OCRv4 模型到 `~/.paddleocr/`；faster-whisper 首次下载 `small` 模型（~500MB）。

## 3. MySQL 准备（开发期，本机）


```sql

CREATE USER IF NOT EXISTS 'edumentor'@'localhost' IDENTIFIED BY 'edumentor123';
```

## 4. 配置 `.env`（开发期）

```bash
cp .env.example .env
```

```dotenv
# LLM：开发用 DeepSeek 云 API
LLM_PROVIDER=deepseek
DEEPSEEK_API_KEY=sk-你的DeepSeekKey
DEEPSEEK_BASE_URL=https://api.deepseek.com/v1
DEEPSEEK_MODEL=deepseek-v4-flash

# Embedding：开发用千问云 API
EMBEDDING_PROVIDER=qwen
QWEN_API_KEY=sk-你的千问Key
QWEN_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
QWEN_EMBEDDING_MODEL=text-embedding-v4

# 数据库（MySQL）
DATABASE_URL=mysql+pymysql://edumentor:edumentor123@127.0.0.1:3306/edumentor?charset=utf8mb4

# 向量库 / 缓存：开发用轻量后端
VECTOR_BACKEND=faiss
VECTOR_INDEX_DIR=data/vector_index
CACHE_BACKEND=memory

APP_PORT=8000
UPLOAD_DIR=data/uploads
APP_ENV=dev
```

> 本地无 Ollama / Milvus / Redis 也能跑通全部功能（FAISS + 内存缓存）。

## 7. 常见问题（开发期 FAQ）

| 问题 | 排查 |
|------|------|
| MySQL 连不上（Access denied） | 确认已执行 §3 建用户；确认 `DATABASE_URL` 账号密码一致 |
| `pymysql` 报 `cryptography` 缺失 | MySQL8 认证需要：`pip install cryptography` |
| `paddleocr` 安装失败 / 3.x 报 `use_angle_cls` | 先装 `paddlepaddle` CPU 版 + `paddleocr>=2.7,<3.0`，勿装 3.x |
| LLM 报 401/限流 | 检查 `.env` 的 `DEEPSEEK_API_KEY` / `QWEN_API_KEY`；确认余额 |
| 端口被占用 | `uvicorn --port 8001` 并同步 `APP_PORT` |
| WSL2 方案 | `sudo apt install -y libgl1 libglib2.0-0`（PaddleOCR 依赖） |

## 8. 生产期部署（Ubuntu + RTX 4090）

> **若中间件（MySQL/Redis/Milvus）已在服务器部署，跳过 §8.1，直接从 §8.2 开始。** 应用不直接连 MinIO（它是 Milvus 内部对象存储），只需 Milvus 的 `MILVUS_HOST`/`MILVUS_PORT`。

### 8.1（可选/备用）中间件未预装时，用 docker-compose 一键起

> 仅当目标机**没有**现成中间件时使用；已部署则整节跳过。

```bash
# 1. 安装 Docker + compose 插件（略）
# 2. 在项目根目录启动全部中间件
docker compose -f docker-compose.prod.yml up -d
docker compose -f docker-compose.prod.yml ps   # 全部 healthy 后继续
```

`docker-compose.prod.yml`（项目根目录）要点：

```yaml
services:
  mysql:
    image: mysql:8.0
    environment:
      MYSQL_ROOT_PASSWORD: root123
      MYSQL_DATABASE: edumentor
      MYSQL_USER: edumentor
      MYSQL_PASSWORD: edumentor123
    ports: ["3306:3306"]
    volumes: [mysql_data:/var/lib/mysql]
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost"]
      interval: 10s
      timeout: 5s
      retries: 5

  redis:
    image: redis:7
    ports: ["6379:6379"]
    volumes: [redis_data:/data]

  etcd:
    image: quay.io/coreos/etcd:v3.5.5
    environment:
      - ETCD_AUTO_COMPACTION_MODE=revision
      - ETCD_AUTO_COMPACTION_RETENTION=1000
      - ETCD_QUOTA_BACKEND_BYTES=4294967296
    volumes: [etcd_data:/etcd]
    command: etcd -advertise-client-urls=http://127.0.0.1:2379 -listen-client-urls http://0.0.0.0:2379 --data-dir /etcd
    healthcheck:
      test: ["CMD", "etcdctl", "endpoint", "health"]
      interval: 10s
      retries: 5

  minio:
    image: minio/minio:RELEASE.2023-03-20T20-16-18Z
    environment:
      MINIO_ACCESS_KEY: minioadmin
      MINIO_SECRET_KEY: minioadmin
    command: minio server /minio_data --console-address ":9001"
    ports: ["9000:9000", "9001:9001"]
    volumes: [minio_data:/minio_data]
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:9000/minio/health/live"]
      interval: 10s
      retries: 5

  milvus:
    image: milvusdb/milvus:v2.4.1
    command: ["milvus", "run", "standalone"]
    security_opt: [seccomp:unconfined]
    environment:
      ETCD_ENDPOINTS: etcd:2379
      MINIO_ADDRESS: minio:9000
    ports: ["19530:19530", "9091:9091"]
    volumes: [milvus_data:/var/lib/milvus]
    depends_on: [etcd, minio]

volumes:
  mysql_data: {}
  redis_data: {}
  etcd_data: {}
  minio_data: {}
  milvus_data: {}
```

### 8.2 部署本地模型（Ollama，RTX 4090）

```bash
# 安装 Ollama（curl -fsSL https://ollama.com/install.sh | sh）
ollama pull qwen2.5:14b     # 对话/决策 LLM（4090 24G 可跑 14B Q4）
ollama pull bge-m3          # 向量 Embedding（1024 维）
ollama serve                # 默认 OpenAI 兼容端点 http://localhost:11434/v1
```

> 验证：`curl http://localhost:11434/v1/models`。vLLM 亦可（`vllm serve Qwen/Qwen2.5-14B-Instruct --served-model-name qwen2.5:14b`），本项目按 Ollama 的 OpenAI 兼容端点对接。

### 8.3 配置 `.env`（生产期）

```dotenv
LLM_PROVIDER=local
LOCAL_LLM_BASE_URL=http://localhost:11434/v1
LOCAL_LLM_MODEL=qwen2.5:14b

EMBEDDING_PROVIDER=local
LOCAL_EMBEDDING_BASE_URL=http://localhost:11434/v1
LOCAL_EMBEDDING_MODEL=bge-m3

DATABASE_URL=mysql+pymysql://edumentor:edumentor123@127.0.0.1:3306/edumentor?charset=utf8mb4
VECTOR_BACKEND=milvus
MILVUS_HOST=127.0.0.1
MILVUS_PORT=19530
CACHE_BACKEND=redis
CACHE_URL=redis://127.0.0.1:6379/0

APP_PORT=8000
UPLOAD_DIR=data/uploads
APP_ENV=prod
```

### 8.4 初始化 + 启动（生产期）

```bash
pip install -r requirements.txt
python scripts/init_db.py        # 向已部署的 MySQL 建表（库与用户需预先存在，见 §3）
python scripts/build_kb.py       # 重建向量索引到 Milvus（bge-m3 嵌入）
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

## 9. 从笔记本迁移到 Ubuntu 的检查清单

- [ ] 代码、`docs/`、`scripts/`、`demo_data/` 完整同步（数据目录 `data/` 与 `.env` 不提交 git）
- [ ] 确认 MySQL/Redis/Milvus 已在服务器运行并可达（`mysqladmin ping` / `redis-cli ping` / Milvus 客户端连接测试）；`DATABASE_URL`、`CACHE_URL`、`MILVUS_HOST/PORT` 指向正确
- [ ] （仅当未预装中间件时）`docker compose -f docker-compose.prod.yml up -d` 全部 healthy
- [ ] Ollama 已部署 `qwen2.5:14b` 与 `bge-m3`；`/v1/models` 可访问
- [ ] `.env` 切换为生产值（§8.3），`APP_ENV=prod`
- [ ] `pip install -r requirements.txt` 成功（含 `pymilvus`、`redis`）
- [ ] `python scripts/init_db.py` 成功
- [ ] `python scripts/build_kb.py` 成功（索引写入 Milvus）
- [ ] 服务启动后 `GET /api/v1/health` 返回 `{"status":"ok",...}`
- [ ] curl 一条答疑流式请求正常返回（验证本地 LLM + Milvus 检索链路）
- [ ] curl 一次作业批改（验证 PaddleOCR 在服务器可用，必要时 `libgl1`）

> **代码零改动**：全部差异收敛在 `.env` 与中间件运行状态。若迁移后报后端缺失，先查 `VECTOR_BACKEND`/`CACHE_BACKEND`/`LLM_PROVIDER` 是否已切换。

## 10. 演示脚本建议（答辩前准备）

1. **答疑**：文字提问「什么是注意力机制？」→ 展示溯源引用。
2. **答疑多模态**：上传一张题目照片 → 展示 OCR 识别 → 讲解。
3. **批改**：上传作业样例图 → 展示逐题对错与主观题评分。
4. **错题分析**：录入 2~3 道错题 → 展示薄弱知识点 TopN 与讲解。
5. **出题**：指定「RAG 原理 / 困难」生成 → 展示难度差异。
6. **推送**：创建 5 分钟后提醒 → 等 APScheduler 触发 → 查看 `push_logs`。
7. **（生产加分项）**：演示中间件连通（`redis-cli ping` + MySQL 可连 + Milvus 集合存在；若用 compose 则 `docker compose ps` 全绿）→ 佐证企业级中间件部署。
